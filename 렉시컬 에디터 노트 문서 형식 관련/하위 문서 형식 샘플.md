# 하위 문서 형식 샘플

이 문서는 TODO 하나를 담당하는 하위 문서의 기준 샘플이다. Step마다 별도 문서를 만들지 않고, 하나의 TODO 하위 문서 안에서 Step 1~N을 순서대로 작성한다.

## Lexical 블록 순서

```text
h1  TODO 제목
quote
  TODO의 목적과 기대 결과

h2  Step 1. 작업명
quote
  이번 Step에서 할 한 가지 작업과 확인 결과
paragraph
  파일:
code(language=text)
  실제 파일 경로
paragraph
  코드:
code(language=실제 언어)
  함수·훅·컴포넌트·설정 단위의 실제 구현 코드
paragraph
  필요한 경우에만 주의사항:
quote
  비자명한 설계 판단
paragraph
  실제 검증을 실행한 경우에만 검증:
quote
  명령과 결과

h2  Step 2. 작업명
quote
  다음 작업 설명
...
```

`파일:`과 `코드:`는 일반 paragraph로 표시하고, 그 아래의 경로와 코드는 quote 밖에 독립된 code 블록으로 둔다. 각 code 블록 뒤에는 빈 paragraph 1개를 두고, 다음 Step 전에는 빈 paragraph 2개를 둔다. 파일 경로 code 블록의 언어는 `text`, 실제 코드 블록의 언어는 `java`, `typescript`, `tsx`, `bash`, `json` 등 실제 문법에 맞게 지정한다.

코드는 몇 줄만 떼어낸 부분 코드가 아니라 독자가 흐름을 이해할 수 있는 함수·훅·컴포넌트·설정 단위로 기록한다. `...` 같은 설명용 생략 표기는 사용하지 않는다. TypeScript의 서버 응답 타입·화면 모델·변환표·페이지 응답처럼 역할이 중요한 주요 타입 위에는 한 줄 주석을 포함한다. `주의사항`과 `검증`은 설계 판단이나 실제 실행 결과가 있을 때만 추가한다.

## 화면 예시

# TODO 1. 실제 LOT API 호출과 응답 매핑 구현

> 서버의 LOT 목록 응답을 프론트 모델로 변환하고 화면에서 사용할 수 있게 한다.

## Step 1. API 함수 구현

> 실제 서버 계약을 확인한 뒤 API 호출 함수와 응답 매핑을 구현한다.

파일:

```text
prac-pkt-react/src/features/lot/api/lot.api.ts
```

코드:

```typescript
export async function fetchLots(page: number, size: number) {
  const response = await fetch(`/api/lots?page=${page}&size=${size}`);
  if (!response.ok) throw new Error("LOT 목록 조회에 실패했습니다.");
  return response.json();
}
```

구현 완료 후에는 실제 변경 코드와 Step 설명을 기록한다. 설계 판단이나 실제 실행 결과가 있을 때만 주의사항·검증을 추가한다. 아직 구현하지 않은 단계에는 예시 코드를 실제 구현 코드처럼 작성하지 않는다.
