# P&T LOT 품질 판정 데이터베이스 설계

## 목적과 범위

> 이 설계는 설비가 측정한 전류·전압 데이터를 저장하는 모델이 아니라, 이미 존재하는 LOT의 수량·수율·불량률·상태를 종합해 출하 가능 여부를 판정하는 모델이다.

## 핵심 관계

```text
products ─┬─ work_orders ─┬─ lots ─ lot_quality_judgements ─ lot_quality_judgement_results
          │               │
          └─ lot_quality_standards ─ lot_quality_rules
```

`work_orders`, `lots`, `products`는 현재 생산 실행과 기준정보에서 사용 중인 테이블을 재사용한다. 새 테이블은 LOT 품질 기준과 그 적용 이력만 소유한다.

## 기존 테이블의 역할

| 테이블 | 책임 | 품질 판정에서 사용하는 값 |
| --- | --- | --- |
| `products` | 제품 기준정보 | 적용 제품, 제품 구분, 활성 상태 |
| `work_orders` | 생산 지시 | 작업지시 코드, 계획 수량, 상태 |
| `lots` | 실제 생산 단위 | LOT 번호, 제품, 계획 수량, 공정, 상태, 정상/불량 수량, 수율 |

LOT의 정상·불량·수율은 이후 실제 Tester 또는 품질 시스템이 제공할 수 있다. 1차 프로토타입은 시드 데이터 또는 화면에서 확보된 결과값을 판정 원천으로 사용한다.

## 1. lot_quality_standards

제품별 LOT 품질 판정 기준의 헤더다. 한 제품에 여러 기준과 버전을 둘 수 있다.

| 컬럼 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | bigint | PK |
| `product_id` | bigint | `products.id` FK, not null |
| `standard_name` | varchar(150) | 예: `PKT-C 출하 기준`, not null |
| `version` | integer | 1 이상, not null |
| `status` | varchar(20) | DRAFT, APPROVED, INACTIVE |
| `required_lot_status` | varchar(30) | 기본 `COMPLETED` |
| `pass_disposition` | varchar(20) | 기본 `SHIP` |
| `fail_disposition` | varchar(20) | 기본 `HOLD` 또는 `RETEST` |
| `description` | varchar(500) | nullable |
| `approved_at` | timestamp | nullable |
| `created_at`, `updated_at` | timestamp | not null |

고유 제약은 `(product_id, standard_name, version)`으로 둔다. `APPROVED` 상태의 헤더와 하위 조건은 수정·삭제하지 않고 새 버전을 생성한다.

## 2. lot_quality_rules

하나의 기준에 속한 개별 판정 조건이다. 1차 구현은 아래 네 지표를 지원한다.

| 컬럼 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | bigint | PK |
| `quality_standard_id` | bigint | `lot_quality_standards.id` FK, not null |
| `display_order` | integer | 기준 안에서 unique, 1 이상 |
| `metric` | varchar(30) | `YIELD_RATE`, `DEFECT_RATE`, `PASS_QUANTITY`, `LOT_STATUS` |
| `operator` | varchar(10) | `GTE`, `LTE`, `EQ` |
| `threshold_decimal` | decimal(12,4) | 수치 지표에서 not null |
| `threshold_text` | varchar(50) | 상태 지표에서 not null |
| `label` | varchar(150) | 화면 표시 문구 |
| `created_at`, `updated_at` | timestamp | not null |

| 지표 | 허용 비교 | 기준값 검증 |
| --- | --- | --- |
| `YIELD_RATE` | `GTE` | 0~100 |
| `DEFECT_RATE` | `LTE` | 0~100 |
| `PASS_QUANTITY` | `GTE` | 0 이상 정수 |
| `LOT_STATUS` | `EQ` | LOT 상태 문자열 |

예시: `PKT-C 출하 기준 v1`

| 순서 | metric | operator | 기준값 | 화면 문구 |
| --- | --- | --- | --- | --- |
| 1 | `LOT_STATUS` | `EQ` | `COMPLETED` | LOT 상태가 완료여야 합니다. |
| 2 | `YIELD_RATE` | `GTE` | 98.0000 | 수율은 98.0% 이상이어야 합니다. |
| 3 | `DEFECT_RATE` | `LTE` | 2.0000 | 불량률은 2.0% 이하여야 합니다. |
| 4 | `PASS_QUANTITY` | `GTE` | 2000 | 정상 수량은 2,000 EA 이상이어야 합니다. |

## 3. lot_quality_judgements (스텝4 예정)

기준을 특정 LOT에 적용한 한 번의 판정 실행 이력이다. 스텝3에서는 생성하지 않으며 설계만 고정한다.

| 컬럼 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | bigint | PK |
| `lot_id` | bigint | `lots.id` FK, not null |
| `quality_standard_id` | bigint | `lot_quality_standards.id` FK, not null |
| `standard_name_snapshot`, `standard_version_snapshot` | varchar/integer | 실행 시점 기준 |
| `lot_status_snapshot` | varchar(30) | 실행 시점 LOT 상태 |
| `input_quantity_snapshot`, `pass_quantity_snapshot`, `fail_quantity_snapshot` | integer | 실행 시점 집계값 |
| `yield_rate_snapshot`, `defect_rate_snapshot` | decimal(12,4) | 실행 시점 비율 |
| `final_disposition` | varchar(20) | SHIP, RETEST, HOLD |
| `status` | varchar(20) | PASSED, FAILED |
| `judged_at` | timestamp | not null |

## 4. lot_quality_judgement_results (스텝4 예정)

한 번의 판정에서 각 조건이 왜 통과·실패했는지 보존한다.

| 컬럼 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | bigint | PK |
| `judgement_id` | bigint | `lot_quality_judgements.id` FK |
| `rule_order_snapshot` | integer | 실행 시점 순서 |
| `metric_snapshot`, `operator_snapshot` | varchar | 실행 시점 조건 |
| `expected_value_snapshot`, `actual_value_snapshot` | varchar(50) | 기준값·실제값 |
| `result` | varchar(10) | PASS, FAIL |
| `message` | varchar(300) | 통과·실패 설명 |

## 상태와 처분의 구분

```text
LOT 상태:  대기 / 진행 / 완료 / 보류
판정 상태: PASSED / FAILED
판정 처분: SHIP / RETEST / HOLD
```

LOT 상태는 생산 실행 흐름의 상태이고, 판정 처분은 품질 기준 적용 결과다. 판정 실패가 항상 LOT 상태 변경을 의미하지는 않는다. 스텝4에서만 최종 처분에 따라 LOT을 보류 또는 재검으로 전환할지 결정한다.

## 스텝3 검증 기준

- 활성 제품에만 신규 품질 기준을 등록할 수 있다.
- 기준에는 상태 조건을 포함해 최소 한 개 이상의 조건이 있어야 한다.
- 승인된 기준은 변경할 수 없고 새 버전을 생성해야 한다.
- 위 지표별 연산자·기준값 범위를 서버가 검증한다.
- 기준 목록과 선택한 기준의 조건 테이블이 같은 데이터로 조회된다.
