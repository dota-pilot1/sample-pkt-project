# 현재 구조와 전환 범위

## 현재 실행 구조

```text
pkt-study-tauri
├── React 19 + Vite 6 UI
├── Tauri 2 데스크톱 셸
├── Tauri HTTP 플러그인으로 외부 API 호출
└── GitHub Release updater

sk-pkt-mes-server
├── Spring Boot API
├── Spring Security + JWT access/refresh token
├── JPA
└── PostgreSQL
```

설치된 Tauri 앱은 자체 데이터를 보유하지 않고 `VITE_API_BASE`로 지정한 Spring API에 연결한다. 로컬 개발 API 기본값은 `http://localhost:4201`이다.

## 현재 앱에서 확인된 기능

### 메인 화면에 연결된 기능

- 로그인, 세션 복원, 로그아웃
- 플레이북 공간 목록
- 카테고리·주제·문서 트리
- 문서 검색
- Lexical 문서 조회·생성·수정·삭제·승인
- 문서 및 하위 문서 순서 변경
- 문서 댓글
- 공개 공유 토큰과 AI 편집 토큰
- 이미지 업로드용 presigned URL
- 프로필·설정 화면
- Tauri 창 제어, 클립보드, updater
- PostgreSQL dump/restore 기반 DB 동기화 command

### 소스는 있지만 현재 메인 화면에 연결되지 않은 기능

- 키오스크 챗봇
- 상담 handoff
- 키오스크 analytics

이 세 기능은 삭제 대상으로 간주하지 않는다. 1차 전환 전에 실제 사용 여부를 확인하고 `이전`, `보류`, `제거` 중 하나로 표시한다.

## 서버 범위 구분

`sk-pkt-mes-server`에는 플레이북 외에도 LOT, BOM, 생산계획, 작업지시, 메뉴 등 MES 기능이 있다. 현재 데스크톱 학습 노트 앱을 독립 풀스택 앱으로 만드는 작업에서는 다음처럼 구분한다.

### 1차 필수

- auth
- user의 로그인 사용자 조회에 필요한 부분
- role, permission의 인가 판정에 필요한 부분
- playbook
- upload
- 앱 설정과 초기 관리자 생성

### 사용 여부 확인 후 결정

- kiosk session/message/handoff/analytics
- LLM 전용 공개 API
- 공개 문서 공유 API
- 온라인 S3 이미지 업로드

### 1차 범위 제외

- lot
- bom
- productionplan
- workorder
- MES 웹 관리 화면 전용 API

## 목표 코드 경계

```text
pkt-study-fullstack/
├── src/app/                 Next.js App Router와 Route Handler
├── src/features/            기존 React 기능 이전
├── src/server/              인증, 서비스, DB 접근
├── src/db/                  Drizzle schema와 migration
├── src-tauri/               실행, 로컬 파일, 백업, updater
└── data/                    개발용 SQLite 위치만 사용
```

운영 DB는 설치 폴더가 아니라 Tauri의 앱 데이터 디렉터리에 둔다. 앱 업데이트가 설치 파일을 교체해도 사용자 DB가 보존되어야 한다.

## 반드시 먼저 검증할 항목

- Next.js standalone 서버가 Tauri 설치 파일 안에서 실행되는지
- 설치 대상 PC에 별도 Node.js 설치 없이 실행되는지
- 사용 가능한 로컬 포트를 안전하게 선택하고 앱 창이 해당 주소를 여는지
- 앱 종료 시 sidecar 서버가 함께 종료되는지
- `better-sqlite3` 네이티브 모듈이 macOS와 Windows 패키지에 포함되는지
- 앱 데이터 디렉터리의 SQLite 파일에 읽기·쓰기가 가능한지

이 검증이 실패하면 UI 이전을 중단하고 런타임 구성을 먼저 수정한다.
