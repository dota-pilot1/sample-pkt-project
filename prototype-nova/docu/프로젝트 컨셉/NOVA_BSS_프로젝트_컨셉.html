NOVA · PROJECT CONCEPT

차세대 BSS 운영 플랫폼: NOVA

NOVA는 단순 관리 화면 교체가 아니라 고객·상품·주문·개통·과금을 다루는 통신 BSS의 변경 속도와 운영 유연성을 높이는 학습용 운영 플랫폼이다.

문서 성격: 프로젝트 설계 가정 · SWING, NOVA, 전환 일정 등 외부 기사·채용공고의 고유 명칭과 일정은 별도 출처 검증이 필요하다. 이 문서는 이를 사실 확정이 아닌 설계 맥락으로 사용한다.

1. 한 문장으로 정의

“새 요금제나 결합상품의 기획부터 전산 적용까지 걸리는 시간을 줄이기 위해, BSS의 핵심 업무를 도메인 단위로 분리하고 변경 영향도를 낮춘다.”

현재의 문제

상품 하나의 변경도 여러 시스템과 규칙에 걸려 검토·개발·검증 범위가 넓어진다.

설계 원칙

각 업무의 책임과 데이터 소유권을 분명히 하고, API 계약으로 연결한다.

기대 효과

상품·요금·주문 정책의 변경을 독립적으로 배포하고 이력까지 추적한다.

2. 목표 아키텍처

클라우드 기반 MSA

모든 것을 처음부터 마이크로서비스로 나누지 않는다. 단일 애플리케이션에서 도메인 경계와 API 계약을 검증한 뒤, 독립 배포·확장 필요가 확인된 영역만 분리한다.

하이브리드와 보안

클라우드 활용과 별개로 개인정보·민감정보의 보관·접근 경계를 명시한다. 외부 연동 데이터와 내부 보호 데이터의 책임을 구분한다.

상품·요금 유연성→AI / CX→6G 상품화→슬라이싱 과금

3. NOVA BSS 도메인 지도

각 칸은 나중에 독립 서비스 후보가 될 수 있는 업무 경계다. 지금은 데이터 모델·정책·API 책임을 섞지 않는 기준으로 쓴다.

5. 학습·구현 로드맵

1
요금제 관리

CRUD, 정책 검증, 판매 상태, 버전 충돌, 변경 이력을 일관되게 만든다. 진행 중

2
상품 관리 · 고객 관리 · 계약

판매 대상과 가입 주체·조건을 모델링한다.

3
Customer Order

고객의 가입·변경 요청을 독립된 상태와 이력으로 관리한다.

4
Resource Order · Fulfillment

주문을 자원 작업으로 변환하고, 심사·개통 성공·실패를 추적한다. 채용 영역 직접 연결

5
Billing · 권한 · 감사로그

과금 결과와 운영 통제를 더해 실제 BSS 흐름을 완성한다.

6
검증된 경계만 MSA로 분리

도메인 경계, 데이터 소유권, 장애 격리, 배포 주기가 맞는 곳부터 분리한다.

6. 현재 구현과 다음 우선순위

현재 기반

요금제 분류·목록·생성/수정·상태 전이·변경 이력과 가입(Subscription) 모델을 발전시키는 단계다.

다음 구현

ACTIVE 요금제를 선택한 고객 가입 신청을 Customer Order로 명확히 하고, 심사와 개통 상태를 Fulfillment로 분리한다.
