SKT NOVA 공고 통합 분석
그리고 학습 전략

공고 11개 캡처를 역할별로 묶으면 중심은 명확하다. 통신 BSS/OSS의 복잡한 업무를 Java/Spring·React·Oracle 기반으로 현대화하고, 배치·관측·컨테이너 운영을 갖춘 뒤 AI/LLM을 업무 흐름에 안전하게 붙일 수 있는 개발자다.

공고 해석 NOVA 도메인 우선 학습 실습 프로젝트 지원 전략 캡처 목록 전체 공고 로드맵

이 공고들이 진짜로 찾는 사람

단순한 Java 코더도, LLM 데모 제작자도 아니다. 가입·상품·주문·개통·자원·과금·고객 업무를 이해하고, 레거시 C/WebSquare/Swing 환경을 Java/Spring·React로 옮기며, 운영 지표와 AI 기능까지 연결할 수 있는 업무 시스템 현대화 개발자다.

AS-IS 분석→업무·데이터 모델→Java/Spring API→React UI→Batch·Oracle→Monitoring→AI 업무 보조

공고를 5개 역할로 읽기

1. NOVA 업무 현대화

유·무선 가입, 상품, 재무, PRM, CRM, OSS, BSS 전반을 다룬다. Java, Spring Boot, React, Oracle과 AI/LLM 경험을 요구 또는 우대한다.

JavaSpring BootReactBSS/OSS

2. 레거시 전환

Biz는 C → Java, UI는 WebSquare → React 전환 인력을 별도로 찾는다. Billing·상품·오더·OSS·채널 업무와 통신사 운영 경험이 우대다.

C to JavaWebSquare to ReactOrder

3. NOVA 도메인 백엔드

Java 중급 이상, 유선 통신과 Swing 경험을 우대하며 Billing, CRM, EPC, Offering, Partner, Order·Fulfillment를 명시한다.

BillingCRMFulfillment

4. 과금 시스템 개선

현 시스템·현업 요구 분석, 모니터링 요건 적용이 중심이다. Spring Batch, Oracle SQL, InfluxDB, Grafana, Prometheus, Docker, K8s가 함께 나온다.

Spring BatchPrometheusK8s

5. Go 기반 연동·고성능

C++ 기반 연동 솔루션 설계·개발, Go 외부 연계 API, 실시간 처리, Docker/Kubernetes/DevOps를 요구한다. NOVA 핵심과는 별개의 고성능·플랫폼 확장 트랙이다.

GoTCP/UDPMicroservice

6. 차세대 AI Agent 활용 개발

Java 기반 프로그램 개발 위에 AI Agent를 활용한 요구사항 개발을 올린다. React, Spring Boot/Spring/Java, AI Agent 활용 경험을 요구하며 통신 업무 경험은 필수가 아니고 Agent 개인 프로젝트도 인정한다.

Java·SpringReactAI Agent

공통으로 반복되는 신호

업무 분석·설계 능력, 실제 운영 경험, 통신 도메인, 안정적 배치/관측, 그리고 AS-IS를 TO-BE로 옮기는 문서화 역량이 반복된다.

요구분석설계운영
핵심 해석: AI/LLM은 NOVA 공고에서 우대 또는 전환 방향으로 제시되지만, 가장 강한 기본 자격은 통신 업무 분석과 Java/Spring·React·Oracle로 업무 시스템을 구현·운영하는 힘이다. 다만 새 AI Agent 활용 공고는 통신 경력이 없어도 Java/Spring·React 기반의 Agent 프로젝트 경험이 있으면 진입할 수 있음을 보여준다. 그래도 도메인·API·권한·검증 없이 챗봇만 만드는 순서는 맞지 않는다.

NOVA 통신 도메인 지도

공고에 반복된 용어를 학습 구조로 바꾸면 아래처럼 연결된다. 한 용어씩 암기하기보다 고객 요청이 주문·자원·개통·청구까지 어떻게 흐르는지 이해하는 것이 목표다.

고객·파트너 ├── CRM : 고객, 상담, 관계, 이력 ├── Partner / PRM : 대리점·파트너와 판매 채널 ├── Product / Offering │ ├── 상품 정의, 요금제, 할인, 판매 조건 │ └── Marketing & Offering ├── Product Order : 고객의 가입·변경·해지 주문 ├── Service Order : 서비스 제공을 위한 작업 지시 ├── Resource Order : 회선·장비·번호 등 자원 작업 지시 ├── Resource & Fulfillment │ └── 자원 할당, 개통, 제공 완료 확인 ├── Billing / Finance : 과금, 청구, 수납, 정산 └── OSS / EPC : 망·자원·운영·개통 연계

EPC, OSS/BSS, Order 용어는 회사·프로젝트마다 세부 경계가 다를 수 있다. 면접과 실무에서는 공고 용어를 그대로 외우기보다, 해당 조직의 실제 주문·개통·청구 흐름을 확인하며 모델을 맞춘다.

AS-IS → TO-BE 포트폴리오 서사

수기·레거시 업무→요구사항·데이터 분석→Java/Spring API→React 업무 화면→Batch·모니터링→AI 보조·승인
  • AS-IS: 상품 변경과 개통 상태 확인이 여러 시스템과 수작업 조회에 흩어져 있고, 배치 실패 원인도 즉시 찾기 어렵다.
  • TO-BE: 주문·자원 상태를 하나의 화면에서 추적하고, Batch 처리·실패·재처리 이력을 운영 대시보드에서 확인한다.
  • AI 적용: 정책 문서와 상품 데이터를 근거로 자연어 검색·영향 분석 초안을 만들되, 실제 변경은 권한과 승인 후에만 실행한다.
  • 검증: 상태 전이 테스트, Batch 재실행 테스트, 모니터링 화면, AI 출처·Tool 호출·Audit Log를 함께 제시한다.

  • Spring Batch의 Job/Step, 재시작, 중복 방지를 구현했다.
  • React에서 업무 Table, Form, 권한, 오류 상태를 구현했다.
  • WebSquare/Swing/C 레거시 전환 시 위험과 점진 전환 방법을 말할 수 있다.

  • Docker와 Kubernetes Job/CronJob의 역할을 구분한다.
  • AI가 SQL이나 변경 API를 직접 실행하지 않도록 설계했다.
