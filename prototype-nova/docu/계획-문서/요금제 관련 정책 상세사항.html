NOVA · 요금제

요금제 운영 정책 상세사항

요금제를 만들고 판매할 때 지켜야 할 약속을 정리한 문서다. DB와 API를 만들기 전에 이 문서를 먼저 검토하고, 제안 항목만 확정하면 된다.

문서 상태: 초안 · 아래 제안은 학습용으로 잡은 기본안이다. 실제 개발 시작 전 팀의 결정으로 바꾸거나 확정한다.

1. 이 문서에서 정할 것

정하는 것

요금제를 언제 판매할지, 언제 멈출지, 등록할 때 무엇을 꼭 넣을지, 삭제는 어떻게 할지

지금 정하지 않는 것

고객 가입, 주문, 개통, 할인 계산. 이 기능들은 다음 단계에서 따로 정한다.

2. 판매 상태와 바꾸는 방법

작성 중→판매 시작→판매 중지→완전 종료
현재 상태할 수 있는 일정책상태
작성 중수정, 삭제, 판매 시작이름·종류·월 요금·판매 시작일을 모두 넣었을 때만 판매 시작 가능제안
판매 시작수정, 판매 중지새 고객이 선택할 수 있는 상태. 삭제하지 않음제안
판매 중지다시 판매 시작, 완전 종료새 고객은 선택할 수 없음. 다시 팔 수 있게 할지는 팀이 결정결정 필요
완전 종료조회만 가능다시 판매하지 않음. 기존 기록을 보기 위해 남김제안

3. 등록·수정 규칙

항목규칙상태
요금제 코드다른 요금제와 겹치면 안 되고, 한 번 만든 뒤에는 바꾸지 않는다. 예: PLN-MOB-00001제안
요금제 종류등록 화면에서 사용 중인 종류 하나를 반드시 고른다.제안
이름비어 있으면 저장할 수 없다.제안
한 달 요금0원 이상, 원 단위 정수로 저장한다.제안
판매 기간판매 시작일은 필수. 종료일을 넣으면 시작일보다 빠를 수 없다.제안

4. 삭제와 변경 기록

삭제

제안 아직 판매 시작 전인 “작성 중” 요금제만 삭제할 수 있다. 판매를 시작한 뒤에는 지우지 않고 판매 중지 또는 종료로 남긴다.

변경 기록

제안 이름, 요금, 종류, 판매 상태가 바뀌면 누가·언제·무엇을 바꿨는지 남긴다.

5. 요금제 종류 기준정보

요금제 종류는 plan_categories에서 관리한다. 예: 휴대폰, 데이터 전용, IoT.

  • 제안 새 종류는 추가할 수 있다.
  • 제안 이미 요금제가 쓰고 있는 종류는 바로 삭제하지 않고 “사용 중지”로 바꾼다.
  • 제안 사용 중지된 종류는 새 요금제를 만들 때 선택할 수 없다.

6. 개발 시작 전 체크

1
판매 중지된 요금제를 다시 판매할 수 있나?

가능/불가능 중 하나를 고른다.

2
요금제 코드는 자동으로 만들까, 사람이 입력할까?

자동 생성이면 코드 형식도 같이 정한다.

3
판매 시작 상태에서도 이름·요금을 수정할 수 있나?

가능하다면 변경 기록을 반드시 남긴다.

4
요금제 종류를 누가 추가·중지할 수 있나?

처음에는 관리자만 가능하게 시작해도 충분하다.

5
이 다섯 가지를 확정했나?

확정하면 ERD, API, 테스트 코드에 그대로 반영하고 개발을 시작한다.
