- 대상: `prac-pkt-react`

## `--delete` 안전 확인

`aws s3 sync dist/ s3://hibot-docu-front-hyun0316/ --delete`는 로컬 `dist/`에 없는 S3 객체를 삭제합니다.
따라서 운영 버킷에 웹 파일 외의 자료가 섞여 있으면 실행하지 않습니다.

배포 전 반드시 먼저 확인합니다.

```bash
aws s3 ls s3://hibot-docu-front-hyun0316/ --recursive | head -50
aws s3 sync dist/ s3://hibot-docu-front-hyun0316/ --delete --dryrun
```

dry-run 결과에서 삭제 대상이 예상한 오래된 웹 산출물뿐인지 확인한 뒤 실제 `--delete`를 실행합니다.
확신이 없으면 `--delete` 없이 sync하고, 기존 파일 삭제는 별도로 승인받습니다.

## 검증 및 빌드

```bash
cd /Users/terecal/pilot-project/sample-pkt-project/prac-pkt-react
npm ci
npm run lint
npm run build
```

운영 API URL은 `https://api.hibot-docu.com/api`이다. 이 값은 공개 API 도메인이므로 이 런북에 기록한다. `prac-pkt-react/.env.production`에 같은 값이 저장되어 있으면 이 작업 디렉터리에서는 운영 빌드를 별도 환경변수 없이 만들 수 있다. 다만 `.env.production`은 보안상 Git에서 제외되어 있으므로, 깨끗한 clone에서 자동으로 재현된다는 뜻은 아니다. CI나 다른 개발 환경에서는 이 문서의 URL을 환경변수로 주입한다.

```bash
cat .env.production
VITE_API_BASE_URL=https://api.hibot-docu.com/api npm run build
```

빌드 재현 여부를 상태 보고에 남길 때는 다음을 함께 기록한다.

```bash
test -f .env.production && echo '.env.production exists'
npm run lint
npm run build
```

### 운영 API URL이 레포에 없었는지 확인하는 방법

다음 명령으로 운영 환경 파일이 Git에 추적되지 않고, 어떤 ignore 규칙에 걸리는지 확인한다.

```bash
git ls-files --error-unmatch prac-pkt-react/.env.production
git check-ignore -v prac-pkt-react/.env.production
rg -n "VITE_API_BASE_URL|env.production|env.example" \
  prac-pkt-react .gitignore .git/info/exclude
```

`git ls-files`가 실패하고 `git check-ignore`가 `.env.*` 규칙을 보여주면, 운영 URL은 레포에 없고 현재 로컬 작업 디렉터리에만 있는 상태다. 이 결과와 함께 다음을 기록하면 “운영 URL이 레포에 없어 빌드 재현이 안 됐다”는 판단을 재현할 수 있다.

```text
[변경 전] .env.production 미추적·미존재, 기본값 /api만 사용.
[변경 후] 로컬 .env.production에 운영 API URL 존재.
[검증] 현재 작업 디렉터리에서 npm run build 성공.
[주의] .env.production은 Git에 커밋하지 않으므로 clean clone 재현에는 CI Secret 주입 필요.
```

## 배포

### GitHub Actions 배포

`.github/workflows/frontend-deploy.yml`은 GitHub의 **Actions → Deploy frontend → Run workflow**에서 수동 실행한다. 워크플로가 운영 API URL을 생성하고, 빌드 결과를 S3에 동기화한 뒤 CloudFront cache invalidation과 웹 응답을 확인한다.

`production` Environment에 다음 Secret을 등록한다.

- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`: `ap-northeast-2`
- `FRONTEND_S3_BUCKET`: `hibot-docu-front-hyun0316`
- `FRONTEND_CLOUDFRONT_DISTRIBUTION_ID`: `E1L7QZR4LQV4LE`

현재 워크플로는 배포 실수 방지를 위해 `workflow_dispatch`로만 실행된다.

```bash
aws s3 sync dist/ s3://hibot-docu-front-hyun0316/ --delete
aws cloudfront create-invalidation --distribution-id E1L7QZR4LQV4LE --paths '/*'
```
