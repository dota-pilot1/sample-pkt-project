# 현재 프로젝트 연습 목표

## 1. 목표 배경

현재 프로젝트는 **SK하이닉스 PKT 프로젝트 참여를 준비하기 위한 MES 실무 연습용 프로젝트**다.
인증·인가 보일러플레이트 위에 MES에서 자주 사용하는 도메인과 업무 흐름을 작은 기능 단위로 구현하면서, Spring Boot 백엔드와 React 계열 프론트엔드의 협업 구조를 익히는 것을 목표로 한다.

> 이 문서는 첨부된 프로젝트 모집/참여 정보와 현재 저장소의 MES 구현 계획을 바탕으로 작성한 학습 목표 문서다.
> 프로젝트의 실제 업무 범위, 담당 역할, 세부 일정은 추후 확정되는 내용을 기준으로 갱신한다.

## 3. 이 저장소에서 달성할 핵심 목표

### 3.1 MES 도메인 이해

- 생산품, 반제품, 원자재의 관계를 이해한다.
- BOM을 이용해 생산에 필요한 자재 소요량을 계산한다.
- 생산계획, 설비 예약, 작업지시, 생산 실적의 연결 관계를 이해한다.
- 생산 진행 상태와 현장 데이터를 모니터링 화면으로 표현한다.

### 3.2 백엔드 실무 역량

- Spring Boot와 Java로 REST API를 설계·구현한다.
- 도메인별 bounded context와 DDD 4-Layer 구조를 적용한다.
- JPA와 PostgreSQL을 이용해 기능별 데이터 모델을 설계한다.
- 요청/응답 DTO, 유효성 검증, 예외 처리, 트랜잭션 경계를 구성한다.
- Swagger에서 API를 확인하고 프론트엔드가 사용할 수 있는 계약을 만든다.
- 기존 JWT 인증·RBAC 권한 구조 위에 MES 기능별 권한을 확장한다.

### 3.3 프론트엔드 실무 역량

- React/Next.js 기반으로 업무 화면을 구현한다.
- 기존 Feature-Sliced Design 구조를 유지하며 기능을 추가한다.
- 목록, 등록·수정 폼, 상태 변경, 필터, 상세 화면의 기본 흐름을 구현한다.
- 생산계획 간트 차트와 모니터링 대시보드처럼 업무 데이터를 시각화한다.
- API 상태, 로딩, 오류, 빈 데이터 상태를 화면에서 처리한다.
- 백엔드 API와 연동되는 사용자 흐름을 완성한다.

### 3.4 협업 및 산출물 역량

- 기능을 DB, API, UI 단위로 나누어 계획한다.
- 기능별 구현 범위와 남은 과제를 문서로 남긴다.
- 도메인 용어와 상태값을 일관되게 관리한다.
- 구현 전 설계와 구현 후 검증 결과를 기록한다.
- 실제 프로젝트에서 설명할 수 있도록 기술 선택과 트레이드오프를 정리한다.

## 4. 구현 연습 범위

현재 권장 순서는 다음과 같다.

1. **BOM 기반 자재 소요량 계산**
   - 품목과 BOM 등록
   - 생산 수량에 따른 자재 소요량 계산
   - 계산 결과 조회
2. **생산계획 등록 및 간트 차트**
   - 생산 품목·수량·기간 등록
   - 계획 상태 관리
   - 기간과 진행 상태 시각화
3. **설비 예약 관리**
   - 설비 등록 및 가용 시간 관리
   - 생산계획과 설비 예약 연결
   - 예약 충돌 검증
4. **작업지시 자동 스케줄링**
   - 생산계획을 공정 단위 작업지시로 분할
   - 작업 순서와 예정 시간 관리
   - 작업지시 상태 변경
5. **생산 모니터링 대시보드**
   - 라인·설비 상태 조회
   - 생산량, 불량량, 가동시간 집계
   - 진행 현황과 이상 상태 시각화

## 5. 기능별 완료 기준

각 기능은 아래 최소 흐름을 만족하면 1차 완료로 본다.

- DB 테이블과 관계가 설계되어 있다.
- 백엔드 CRUD 또는 핵심 업무 API가 동작한다.
- 정상 입력과 주요 오류 케이스를 검증한다.
- Swagger에서 API 요청과 응답을 확인할 수 있다.
- 프론트 메뉴에서 기능 화면으로 이동할 수 있다.
- 화면에서 조회부터 등록·수정·상태 변경까지 핵심 흐름이 동작한다.
- 기능별 문서에 구현 범위와 남은 과제가 기록되어 있다.

## 6. 학습 진행 방식

기능 하나를 다음 순서로 완성한다.

```text
업무 흐름 이해
  → 도메인·상태 정의
  → DB 설계
  → API 설계
  → 백엔드 구현
  → 프론트 화면 구현
  → 연동 및 오류 처리
  → Swagger·화면 검증
  → 문서 및 회고 정리
```

처음부터 전체 MES를 완성하려 하지 않고, 작은 수직 기능 단위를 끝까지 연결하는 방식으로 진행한다. 전체 ERD는 방향만 잡고 실제 테이블과 API는 해당 기능을 구현할 때 확정한다.

## 7. 현재 프로젝트와의 연결

- 백엔드: `mes-prototype-server`의 Spring Boot + Java 구조를 사용한다.
- 프론트엔드: `mes-prototype-front`의 Next.js/React 및 FSD 구조를 사용한다.
- 인증·인가: 기존 JWT와 RBAC 보일러플레이트를 재사용한다.
- 백엔드 구조: `presentation → application → domain`, `infrastructure` 영속성 어댑터 구조를 따른다.
- 프론트 구조: `app → widgets → features → entities → shared` 의존 방향을 따른다.
- 상세 실행 계획: `docs-for-mes 기본 기능 구현 해보기 계획/00-전체-로드맵.md`와 각 기능 폴더의 `PLAN.md`, `DB.md`, `API.md`, `UI.md`를 기준으로 관리한다.

## 10. 프로젝트 성격과 반도체 연계

SK하이닉스 PKT 프로젝트를 준비한다는 관점에서 보면, 최종적으로는 반도체 제조·패키지·테스트 업무와 연결될 가능성을 염두에 둔다. 다만 현재 화면과 샘플 데이터는 의자·테이블을 예시로 사용하는 **일반적인 조립 제조 MES 프로토타입**이다.

따라서 현재 프로젝트의 1차 목표는 제조 MES의 공통 구조를 익히는 것이고, 이후 반도체 도메인으로 확장한다.

```text
일반 제조 MES
품목 → BOM → 재고/MRP → 생산계획 → 작업지시 → 설비 → 생산실적 → 모니터링

반도체 MES 확장
제품/웨이퍼/LOT → 공정 ROUTE → RECIPE/설비 → LOT 실행
→ 검사 결과·수율·불량 → LOT 이력 추적
```

반도체 영역으로 확장할 때는 `공정/라우팅`, `LOT`, `RECIPE`, `검사/수율`, `HOLD·REWORK`, `이력 추적`이 중요해진다. 현재의 BOM/MRP 학습은 제조 시스템의 기본기를 익히는 데 유효하지만, 반도체 MES의 핵심은 최종적으로 **공정 실행과 LOT 이력·수율 관리**에 더 가깝다.

## 11. 메뉴 구조와 권장 학습 순서

현재 메뉴 흐름은 큰 틀에서 적절하다.

```text
대시보드 → BOM/MRP → 생산계획 → 작업지시 → 설비예약 → 모니터링 → 관리
```

다만 업무 개념상 다음과 같이 이해하면 더 자연스럽다.

```text
기준정보
  품목 · 공정/라우팅 · 설비 · BOM · 재고
계획
  MRP · 생산계획
실행
  작업지시 · 설비 배정/예약 · 생산실적
분석
  모니터링 · 품질/수율 · 이력 추적
관리
```

현재 프로젝트에는 아직 `공정/라우팅`, `생산실적`, `품질/수율`, `이력 추적`이 충분히 드러나지 않으므로 향후 추가 학습·구현 후보로 관리한다. `설비예약`은 작업할 공정과 시간이 정해진 뒤에 의미가 생기므로 학습할 때는 작업지시의 앞이나 뒤에서 연결해 본다.

현재 화면 메뉴는 학습 흐름이 보이도록 다음과 같이 구성한다.

```text
메인
기준정보     품목 관리 · 재고 관리 · BOM 관리
계획         MRP 계산 · 생산계획
실행         작업지시 · 작업지시 WBS · 설비 예약
분석         모니터링
학습자료     BOM/MRP ERD · 생산계획 ERD · 매뉴얼 · 코드 리뷰
시스템 관리  사용자 · 역할 · 권한 · 역할-권한 매핑 · 사이트 설정 · 메뉴 관리
```

여기서 `기준정보`는 품목·BOM처럼 생산 업무가 참조하는 데이터이고, `시스템 관리`는 사용자·역할·권한·메뉴처럼 애플리케이션 운영을 위한 기능이다. 둘은 목적이 다르므로 별도 메뉴로 구분한다.

## 12. 프론트엔드 학습 시작점

프론트엔드는 모든 화면을 한 번에 읽기보다, 공통 진입점과 하나의 업무 흐름을 수직으로 따라간다.

### 12.1 공통 구조 먼저 보기

1. [layout.tsx](../mes-prototype-front/src/app/layout.tsx)
   - 전역 Provider, 인증 초기화, 헤더, 전역 토스트가 어디서 조립되는지 확인한다.
2. [Header.tsx](../mes-prototype-front/src/widgets/header/ui/Header.tsx)
   - 서버에서 메뉴를 조회하고, 권한·노출 여부·정렬 순서에 따라 헤더를 만드는 방식을 본다.
3. `src/shared/api/axios.ts`
   - API 기본 주소, JWT 첨부, 공통 오류 처리를 확인한다.
4. `src/app/QueryProvider.tsx`
   - TanStack Query가 프론트의 서버 상태를 어떻게 관리하는지 확인한다.
5. `src/entities/bom/model/types.ts`와 `src/entities/bom/api/`
   - 품목·BOM·재고·MRP의 타입과 API 경계를 먼저 읽는다.

### 12.2 첫 번째로 읽을 수직 기능: 품목 관리

품목 관리는 화면과 API의 연결이 단순하고, BOM·재고·생산계획의 기준이 되므로 첫 학습 대상으로 적절하다.

```text
src/app/bom-mrp/items/page.tsx
  → src/features/bom-mrp/items/ItemManagementGrid.tsx
  → src/entities/bom/api/itemApi.ts
  → src/entities/bom/model/types.ts
  → 백엔드 ItemController/ItemService/ItemRepository
```

이 흐름에서 다음을 확인한다.

- App Router의 `page.tsx`가 실제 화면 Feature를 호출하는 방식
- Feature 컴포넌트가 폼·테이블·mutation을 조합하는 방식
- `useQuery`로 목록을 조회하는 방식
- `useMutation` 후 query cache를 갱신하는 방식
- API DTO와 화면 입력값이 어떻게 연결되는지
- 로딩·오류·빈 목록·성공 토스트를 어떻게 처리하는지

### 12.3 이후 프론트 학습 순서

```text
1. 품목 관리
2. 재고 관리
3. BOM 관리
4. MRP 계산
5. 생산계획 기본
6. 작업지시 관리
7. 작업지시 WBS
8. 설비예약
9. 모니터링 대시보드
```

추천 파일 흐름은 다음과 같다.

| 학습 주제 | 먼저 볼 프론트 파일 |
| --- | --- |
| 품목 | `src/app/bom-mrp/items/page.tsx` → `src/features/bom-mrp/items/ItemManagementGrid.tsx` |
| 재고 | `src/app/bom-mrp/inventories/page.tsx` → `src/features/bom-mrp/inventories/InventoryManagementGrid.tsx` |
| BOM/MRP | `src/features/bom-mrp/boms/BomManagementGrid.tsx` → `src/features/bom-mrp/calculate/MrpCalculateGrid.tsx` |
| 생산계획 | `src/features/production-plans/ProductionPlanBasic.tsx` → `ProductionPlanManual.tsx` |
| 작업지시 | `src/features/work-orders/WorkOrderManagement.tsx` → `WorkOrderWbs.tsx` |
| 모니터링 | `src/features/monitoring/MonitoringDashboard.tsx` |

대시보드는 처음부터 읽기보다 마지막에 보는 편이 좋다. 대시보드는 작업지시와 설비·생산 데이터를 조회·집계해 보여주는 화면이므로, 원천 데이터가 만들어지는 과정을 먼저 이해해야 화면의 지표를 제대로 해석할 수 있다.

### 12.4 프론트엔드에서 최종적으로 익힐 것

- `app`: URL과 화면 진입점
- `features`: 실제 업무 화면과 사용자 행동
- `entities`: 도메인 타입과 API 호출
- `shared`: axios, 공통 UI, 오류·검증 유틸리티
- `TanStack Query`: 서버 데이터 조회·캐시·갱신
- 컴포넌트 상태: 폼 입력, 선택 행, 모달, 필터, 정렬

프론트 학습의 목표는 예쁜 화면을 만드는 것이 아니라, 다음 흐름을 코드로 설명할 수 있게 되는 것이다.
