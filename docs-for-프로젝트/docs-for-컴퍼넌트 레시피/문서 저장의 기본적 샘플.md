# 문서 저장의 기본적 샘플

컴퍼넌트 레시피와 PKT 학습 문서를 저장할 때 사용하는 기본 구조다. 사람이 읽는 Markdown 작성 형식과 서버에 저장되는 Lexical JSON 형식을 함께 설명한다.

## 1. 문서 계층

```text
Space
└── Category (1차 메뉴)
    └── Topic (2차 메뉴)
        └── Document (본문 문서)
            └── Child Document (하위 문서)
```

- `Category`: 큰 학습 영역. 예: `기본 UI 실습`
- `Topic`: 영역 안의 실습 주제. 예: `기본 테이블`
- `Document`: 실습 설명과 코드를 담는 본문. 예: `1. 기본 테이블 만들기`
- `Child Document`: 컴퍼넌트, 페이지 적용, 문법 포인트처럼 분리해서 관리할 세부 문서

본문과 하위 문서는 서로 다른 저장 대상이다. 하위 문서를 만들 때는 본문 API에 다시 저장하지 말고, 하위 문서 생성 API에 부모 Document ID를 `parentId`로 전달한다.

## 2. 기본 문서 순서

실제 구현 순서와 읽는 순서를 맞춘다.

1. 목표
2. 실습 순서 또는 사용 시나리오
3. 컴퍼넌트 책임
4. 데이터 흐름
5. Props와 상태
6. 타입 정의와 데이터 준비
7. 컴퍼넌트 구현
8. 페이지에 적용
9. 실제 동작 확인
10. 설계 포인트
11. PKT 적용 포인트
12. 테스트 체크리스트
13. 문법 포인트

```text
타입·임시 데이터 준비
→ 컴퍼넌트 작성
→ 페이지에 적용
→ 실제 동작 연결
→ 테스트
→ 문법 포인트 정리
```

문법 포인트는 구현 전에 추상적으로 설명하기보다 실제 코드가 완성된 뒤 마지막에 정리한다. 그래야 `map`, `key`, 콜백 props, 상태 업데이트가 현재 코드에서 어떤 역할을 하는지 연결해서 이해할 수 있다.

`파일` 목록은 별도 일반 코드 블록으로 둘 수 있지만, 실제 코드 블록 안에는 항상 파일 경로를 첫 줄 주석으로 넣는다. 예를 들어 `// src/features/lot/ui/LotTable.tsx`처럼 작성한다.

## 4. 코드 블록 규칙

코드 블록은 설명용 문자열이 아니라 실제 복사 가능한 코드로 저장한다.

```tsx
// src/features/lot/ui/LotTableRow.tsx
import type { Lot } from "../model/lot.types";

type LotTableRowProps = {
  lot: Lot;
  onSelect?: (lot: Lot) => void;
};

export function LotTableRow({ lot, onSelect }: LotTableRowProps) {
  const handleSelect = () => onSelect?.(lot);

  return (
    <tr onClick={handleSelect}>
      <td>{lot.id}</td>
      <td>{lot.product}</td>
    </tr>
  );
}
```

다음 규칙을 지킨다.

- 코드 블록의 첫 줄은 `// 실제 파일 경로`다.
- 코드에 필요한 import, 타입, props, 함수, 반환 JSX를 임의로 생략하지 않는다.
- 줄바꿈은 `\n`을 직접 입력하지 말고 실제 줄바꿈으로 작성한다.
- `...`, `생략`, `나머지 동일` 같은 표기는 설명 문장 안에서만 사용한다.
- 파일이 여러 개면 파일별로 코드 블록을 나눈다.
- 언어 표시는 `tsx`, `ts`, `css`, `json`처럼 실제 언어에 맞춘다.

## 5. Lexical JSON 저장 형식

서버의 `content`에는 Markdown 원문이나 일반 텍스트가 아니라 Lexical 직렬화 JSON 문자열을 저장한다. 기본 노드는 `root.children` 순서대로 쌓인다.

```json
{
  "root": {
    "type": "root",
    "version": 1,
    "children": [
      {
        "type": "heading",
        "tag": "h2",
        "children": [{ "type": "text", "text": "목표", "format": 0 }]
      },
      {
        "type": "paragraph",
        "children": [
          { "type": "text", "text": "LOT 테이블을 만든다.", "format": 0 }
        ]
      },
      {
        "type": "code",
        "language": "tsx",
        "children": [
          {
            "type": "code-highlight",
            "text": "// src/features/lot/ui/LotTable.tsx\nexport function LotTable() {}",
            "format": 0
          }
        ]
      }
    ],
    "direction": "ltr",
    "format": "",
    "indent": 0
  }
}
```

저장 시 주의할 점:

- `content` 전체는 JSON 객체가 아니라 JSON 문자열이어야 한다.
- 제목은 `heading`, 일반 설명은 `paragraph`, 코드는 `code` 노드로 저장한다.
- 코드 노드의 실제 코드는 `code-highlight.children[0].text`에 넣는다.
- 코드의 줄바꿈은 `text` 값 안에서 실제 줄바꿈을 유지하며 JSON 직렬화는 저장 시 처리한다.
- 본문에 보이는 순서는 `root.children` 배열 순서와 같아야 한다.
- 빈 줄이 필요하면 임의의 개행 문자를 넣기보다 빈 `paragraph` 노드를 사용한다.

## 6. 행 선택 예시의 책임 분리

행 선택은 자식이 직접 상태를 소유하는 방식이 아니라, 페이지가 상태를 소유하고 행 컴퍼넌트가 콜백을 호출하는 방식으로 작성한다.

```tsx
// src/features/lot/ui/LotTableRow.tsx
import type { KeyboardEvent } from "react";
import type { Lot } from "../model/lot.types";

type LotTableRowProps = {
  lot: Lot;
  onSelect?: (lot: Lot) => void;
  selected?: boolean;
};

export function LotTableRow({ lot, onSelect, selected = false }: LotTableRowProps) {
  const handleSelect = () => onSelect?.(lot);

  const handleKeyDown = (event: KeyboardEvent<HTMLTableRowElement>) => {
    if (event.key === "Enter" || event.key === " ") {
      event.preventDefault();
      handleSelect();
    }
  };

  return (
    <tr
      tabIndex={0}
      aria-selected={selected}
      onClick={handleSelect}
      onKeyDown={handleKeyDown}
    >
      <td>{lot.id}</td>
      <td>{lot.product}</td>
      <td>{lot.status}</td>
      <td>{lot.process}</td>
      <td>{lot.updatedAt}</td>
    </tr>
  );
}
```

```tsx
// src/pages/LotsPage.tsx
const [selectedLot, setSelectedLot] = useState<Lot | null>(null);

<LotTable
  rows={rows}
  selectedLotId={selectedLot?.id}
  onSelect={setSelectedLot}
/>;
```

여기서 `onSelect={setSelectedLot}`은 페이지의 상태 변경 함수를 자식에게 전달하는 것이다. 사용자가 행을 클릭하면 자식의 `handleSelect`가 실행되고, `onSelect?.(lot)`이 현재 LOT를 부모 함수에 전달한다. 부모의 `selectedLot`이 바뀌면 선택 행 강조나 상세 패널이 다시 렌더링된다.

`onSelect?.(lot)`의 `?.`는 콜백이 전달된 경우에만 호출하라는 뜻이다. 읽기 전용 목록에서는 `onSelect`를 생략해도 오류가 나지 않는다. 선택 기능이 필수인 화면이라면 `onSelect`를 필수 props로 선언하는 편이 더 명확하다.

## 7. API 저장 순서

LLM용 API로 문서를 저장할 때는 다음 순서를 지킨다.

```text
기존 tree 조회
→ 구조가 없을 때만 Category·Topic 생성
→ 응답에서 categoryId·topicId 확인
→ 본문 Document 생성 또는 최신 문서 조회
→ 최신 version 확인
→ 본문 content 저장
→ 하위 문서 생성 시 parentId에 부모 Document ID 전달
→ 하위 문서 ids를 원하는 학습 순서로 정렬
→ 다시 tree·document 조회하여 계층과 본문 확인
```

- 구조가 이미 있으면 생성 API를 반복 호출하지 않는다.
- 본문 수정은 최신 `expectedVersion`을 사용한다.
- 버전 충돌이 나면 문서를 다시 조회하고 최신 version으로 재시도한다.
- 하위 문서는 Topic 아래에 만들되 부모 본문과의 관계는 `parentId`로 명시한다.
- 본문 저장 API와 하위 문서 생성 API를 혼동하지 않는다.

### 하위 문서 순서 정렬

하위 문서는 생성된 순서가 학습 순서와 항상 같다고 보장하지 않는다. 생성이 끝나면 같은 Topic과 같은 `parentId`를 가진 문서 ID를 원하는 순서대로 보내고, 다시 트리를 조회한다.

```http
// POST http://localhost:4201/api/llm/hospital-playbook/topics/{topicId}/documents/reorder
Content-Type: application/json

{
  "ids": [
    101,
    102,
    103
  ],
  "parentId": 100
}
```

기본 테이블 실습의 하위 문서 순서는 `컴포넌트 만들기 → 페이지에 적용 → 문법 포인트`로 정렬한다. 정렬 후에는 `tree` 조회로 화면 순서와 `orderIdx`가 의도대로 반영되었는지 확인한다.

## 8. 최종 점검표

- [ ] Category와 Topic이 올바른 공간에 있는가
- [ ] 본문 문서와 하위 문서가 실제 계층으로 분리되어 있는가
- [ ] 문서 제목에 단계와 기능이 드러나는가
- [ ] 실습 순서가 컴퍼넌트 작성 → 페이지 적용 → 동작 확인 순서인가
- [ ] 문법 포인트가 문서 마지막에 있는가
- [ ] 코드 블록 첫 줄에 `// 경로`가 있는가
- [ ] 코드가 실제 줄바꿈을 유지하는가
- [ ] 코드 블록에 함수나 핵심 import를 과도하게 생략하지 않았는가
- [ ] `content`가 올바른 Lexical JSON 문자열인가
- [ ] 하위 문서 생성 시 부모 Document ID를 `parentId`로 사용했는가
- [ ] 하위 문서를 컴포넌트 작성 → 페이지 적용 → 문법 포인트 순서로 정렬했는가
- [ ] 저장 후 다시 조회해 화면과 데이터 계층을 확인했는가
