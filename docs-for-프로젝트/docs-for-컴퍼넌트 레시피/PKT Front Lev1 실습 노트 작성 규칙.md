# PKT Front Lev1 실습 노트 작성 규칙

## 목적

`PKT Front Lev1`은 React와 모던 프론트엔드 기능을 PKT 업무 화면에 적용하며 연습하는 전용 노트다. 컴포넌트 레시피가 재사용 가능한 UI 제조법을 기록한다면, 이 노트는 하나의 화면·기능을 완성하는 실습 과정을 기록한다.

## 1. 기본 계층

```text
PKT Front Lev1
└── 1차 영역: 기본 UI 실습
    └── 2차 주제: 기본 테이블
        ├── 01. 기본 테이블 만들기
        │   ├── 01. 컴포넌트 만들기
        │   ├── 02. 페이지에 적용
        │   └── 03. 문법 포인트
        ├── 02. 상태 Badge 표시
        └── 03. 검색과 필터 추가
```

1차 영역은 학습 단계나 큰 UI 범위로 나눈다. 2차 주제는 하나의 결과물이나 밀접한 기능 묶음으로 만든다. 문서는 한 번에 완료할 수 있는 구현 목표 하나를 다룬다.

## 2. 문서 제목

번호는 학습 순서를 표현하고, 제목만 읽어도 결과물을 알 수 있게 한다.

하위 문서는 실제 구현 흐름에 맞춰 표시 순서도 관리한다. 기본 테이블 실습은 `컴포넌트 만들기 → 페이지에 적용 → 문법 포인트` 순서로 둔다. 문서 생성 순서와 화면 표시 순서가 다를 수 있으므로, 생성 후 `orderIdx`를 별도로 확인한다.

```text
01. 기본 테이블 만들기
01. 컴포넌트 만들기
02. 페이지에 적용
03. 문법 포인트
```

부모 문서는 실습 전체 계획과 완료 기준을 설명한다. 하위 문서는 구현 단계를 나눠 설명한다. 하위 문서가 항상 필요한 것은 아니며, 독립적으로 다시 찾아볼 가치가 있을 때만 만든다.

## 3. 본문 기본 형식

모든 실습 문서는 다음 흐름을 기본으로 한다.

```text
제목
실습 목표
완료 기준
파일
  파일 경로를 text 코드 블록으로 기록
코드
  실제 코드를 tsx/ts/css 등 언어가 지정된 코드 블록으로 기록
적용 포인트
테스트 체크리스트
```

짧은 하위 문서는 `목표 → 파일 → 코드 → 확인할 점` 정도로 줄여도 된다. 프롬프트 전문, 시행착오 전체, 반복된 설명은 저장하지 않고 최종적으로 재사용할 지식만 남긴다.

## 4. 부모 문서와 하위 문서의 역할

부모 문서에는 다음을 기록한다.

- 어떤 PKT 화면을 만드는지
- 화면에 필요한 데이터 모양
- 구현 순서
- 완료 기준
- 다음 실습으로 연결되는 지점

하위 문서에는 다음 중 하나만 집중한다.

- 컴포넌트 책임과 Props
- 페이지 조립과 데이터 전달
- React 문법·상태관리 포인트
- 예외 상태와 테스트

부모 문서와 하위 문서에 같은 코드를 길게 복사하지 않는다. 부모 문서는 최종 조립 구조를 보여주고, 상세 코드는 하위 문서에 둔다.

## 5. PKT 업무 연결

일반적인 예제보다 PKT 업무 용어와 흐름을 우선한다.

```text
기본 테이블 → LOT 목록
행 클릭 → LOT 상세 패널
상태 Badge → 대기·진행 중·완료·이상
검색·필터 → LOT ID·제품·공정 상태
일괄 처리 → 여러 LOT 선택 후 작업 실행
```

각 문서에는 가능하면 다음 중 하나를 포함한다.

- 실제 PKT 화면에서 어디에 쓰이는지
- 사용자의 클릭 흐름
- 서버 API와 연결될 지점
- 로딩·빈 목록·오류·권한 없음 상태

## 6. 파일·코드 블록 규칙

파일 경로와 코드는 분리한다.

```text
파일
src/features/lots/ui/LotTable.tsx

코드
import type { Lot } from "../model/types";

export function LotTable({ lots }: { lots: Lot[] }) {
  return <table>{/* LOT 행 렌더링 */}</table>;
}
```

실제 노트앱에 저장할 때는 파일 경로를 `language: text`, 코드는 `language: tsx`, `ts`, `css` 등으로 지정한 Lexical `code` 블록으로 저장한다. 일반 문단에 코드를 붙여 넣지 않는다.

## 7. 레시피 문서와의 구분

```text
컴포넌트 레시피
→ Button, Table 같은 공통 UI를 어떻게 설계하고 재사용하는가

PKT Front Lev1 실습
→ 그 UI를 LOT, 설비, 공정이력 화면에서 어떻게 조합하고 완성하는가
```

같은 컴포넌트의 Props·variants·접근성 규칙은 레시피 문서를 기준으로 한다. PKT 실습 문서에서는 그 내용을 반복하지 말고, 실제 화면 조합과 업무 흐름에 집중한다.

## 8. 저장 방법

문서 생성과 수정은 노트앱 UI 또는 인증된 플레이북 API를 사용한다.

```text
1. 1차 영역과 2차 주제를 확인한다.
2. 문서 생성 API로 제목과 parentId를 저장한다.
3. GET으로 최신 version과 content를 확인한다.
4. Lexical root.children을 유지하면서 본문 블록을 작성한다.
5. PATCH로 전체 content를 저장한다.
6. 응답의 version과 렌더링 결과를 확인한다.
```

DB 직접 입력은 복구·마이그레이션·장애 보정처럼 API를 사용할 수 없는 경우에만 사용한다. 직접 입력할 때도 Markdown 원문이 아니라 유효한 Lexical JSON 문자열이어야 한다.

- [ ] 코드 블록의 언어가 지정되어 있는가?
- [ ] PKT 화면과 사용자 흐름에 연결되는가?
- [ ] 로딩·빈 상태·오류·권한 상태를 고려했는가?
- [ ] 부모 문서와 하위 문서의 내용이 중복되지 않는가?
- [ ] 기존 레시피 문서와 충돌하는 규칙을 새로 만들지 않았는가?
