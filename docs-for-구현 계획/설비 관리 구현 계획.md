# 설비 관리 구현 계획

## 목표

반도체 공정에서 사용하는 설비 목록을 조회하고, 설비의 현재 상태와 투입 LOT를 확인하며, 관리자가 설비 상태를 변경할 수 있는 React 페이지를 구현한다.

센서·PLC 연동은 이번 범위에서 제외한다. 관리자가 화면에서 상태를 변경하되, 나중에 센서 이벤트를 연결할 수 있도록 상태 변경 이력을 남기는 구조로 설계한다.

## 설비 상태

설비 상태는 학습 목적에 맞게 세 가지로 단순화한다.

| 상태 | 의미 |
| --- | --- |
| `RUNNING` | 현재 생산 또는 작업 수행 중 |
| `IDLE` | 작업이 없거나 운영하지 않는 상태 |
| `MAINTENANCE` | 고장, 정비, 예방점검 중 |

화면에는 다음 한글 라벨을 사용한다.

- 가동 중
- 대기 중
- 점검·수리 중

## 연습 포인트

- 상태값과 화면용 라벨·색상 매핑
- 요약 카드와 목록 데이터의 일관성 유지
- 상태 필터와 검색 조건 조합
- 선택한 행의 상세 패널 또는 모달 표시
- 상태 변경 모달과 폼 검증
- 상태 변경 후 목록과 통계 즉시 갱신
- 현재 상태 변경 이력 타임라인 표시
- 로딩·빈 상태·에러 상태 UI 처리
- 설비 목록을 재사용 가능한 컴포넌트로 분리

## 화면

- 경로: `/equipments`
- 페이지명: 설비 관리

## 화면 구성

### 1. 페이지 헤더

- 제목: 설비 관리
- 설명: 공정 설비의 상태와 투입 LOT를 관리합니다.
- 새로고침 버튼

### 2. 요약 카드

전체 설비 수와 상태별 설비 수를 표시한다.

```text
전체 설비: 12대
가동 중: 8대
대기 중: 3대
점검·수리 중: 1대
현재 가동 비율: 66.7%
```

현재 가동 비율은 직접 입력하지 않고 목록 데이터로 계산한다.

```text
현재 가동 비율 = 가동 중 설비 수 / 전체 설비 수 * 100
```

이 값은 시간 기준 가동률이 아니라, 현재 시점의 설비 가동 비율임을 화면에서 혼동하지 않도록 한다.

### 3. 검색·필터 영역

- 설비명 또는 설비 코드 검색
- 상태 필터: 전체 / 가동 중 / 대기 중 / 점검·수리 중
- 공정 필터: 식각, 증착, 세정 등
- 초기화 버튼

검색어와 필터를 함께 적용할 수 있도록 한다.

### 4. 설비 목록

테이블 또는 카드 목록 중 하나를 선택해 구현한다. 첫 구현은 테이블을 권장한다.

| 컬럼 | 내용 |
| --- | --- |
| 설비 코드 | EQP-ETCH-001 등 |
| 설비명 | Etcher A-01 등 |
| 공정 | 식각, 증착, 세정 |
| 현재 상태 | 상태 뱃지 |
| 투입 LOT | 현재 작업 중인 LOT 또는 `-` |
| 최근 변경 | 상태가 마지막으로 변경된 시각 |
| 액션 | 상세 보기, 상태 변경 |

행을 클릭하면 상세 패널을 열고, 액션 버튼을 클릭하면 해당 기능을 실행한다.

### 5. 설비 상세 패널

선택한 설비의 다음 정보를 표시한다.

- 기본 정보: 코드, 이름, 공정, 설치 위치
- 현재 상태
- 현재 투입 LOT
- 최근 상태 변경 시각
- 최근 상태 변경 사유
- 최근 상태 변경 이력 3~5건

상세 패널은 우측 drawer 또는 modal로 구현한다. 페이지 이동 없이 목록과 상세를 함께 다루는 React 상태 관리 연습을 목표로 한다.

### 6. 상태 변경 모달

관리자가 설비 상태를 변경한다.

- 변경할 상태 선택
- 변경 사유 입력
- 저장 버튼
- 취소 버튼

다음 검증을 적용한다.

- 상태를 선택하지 않으면 저장할 수 없다.
- `점검·수리 중`으로 변경할 때는 사유를 필수로 한다.
- 저장 중에는 버튼을 비활성화한다.
- 저장 성공 후 모달을 닫고 목록·요약 카드를 갱신한다.

## 프론트엔드 타입 예시

```ts
type EquipmentStatus = 'RUNNING' | 'IDLE' | 'MAINTENANCE';

type Equipment = {
  id: number;
  code: string;
  name: string;
  processName: string;
  location: string;
  status: EquipmentStatus;
  currentLotNumber: string | null;
  statusChangedAt: string;
  statusReason: string | null;
};

type EquipmentStatusHistory = {
  id: number;
  equipmentId: number;
  status: EquipmentStatus;
  reason: string | null;
  changedAt: string;
};
```

```text

```

컴포넌트가 모든 상태를 직접 관리하지 않도록 한다. 페이지 또는 커스텀 훅에서 목록·필터·선택 설비 상태를 관리하고, 하위 컴포넌트는 props와 callback을 사용한다.

## 상태 관리 흐름

```text
설비 목록 조회
  → 검색·상태·공정 필터 적용
  → 요약 카드 계산
  → 행 선택 시 상세 패널 표시
  → 상태 변경 모달 저장
  → 목록과 요약 카드 갱신
```

최소한 다음 상태를 연습한다.

- `equipments`: 설비 목록
- `filters`: 검색어와 필터 값
- `selectedEquipment`: 선택된 설비
- `isDetailOpen`: 상세 패널 표시 여부
- `isStatusModalOpen`: 상태 변경 모달 표시 여부
- `isLoading`, `error`: 비동기 상태

## API 초안

처음에는 mock API 또는 로컬 배열로 시작해도 된다. API를 붙이는 경우에는 다음 정도로 단순화한다.

```text
GET   /api/equipments
GET   /api/equipments/{id}
GET   /api/equipments/{id}/status-history
PATCH /api/equipments/{id}/status
```

상태 변경 요청 예시:

```json
{
  "status": "MAINTENANCE",
  "reason": "정기 예방점검"
}
```

상태 변경 주체는 현재 `MANUAL`로 기록한다. 이후 센서·PLC 연동 시에도 동일한 상태 변경 이력에 `SENSOR` 또는 `PLC`를 기록하는 방식으로 확장할 수 있다.

## 구현 순서

1. 설비 타입과 상태 상수 정의
2. 목업 설비 데이터 작성
3. 설비 목록과 상태 뱃지 구현
4. 상태별 요약 카드와 현재 가동 비율 계산 구현
5. 검색·상태·공정 필터 구현
6. 설비 상세 drawer 구현
7. 상태 변경 모달과 입력 검증 구현
8. 상태 변경 후 목록과 요약 카드 갱신 구현
9. 로딩·빈 목록·에러 상태 추가
10. API 연동 또는 기존 백엔드 엔드포인트 연결
11. 주요 시나리오 수동 테스트

## 수동 테스트 시나리오

1. 설비 관리 페이지에 설비 목록과 요약 카드가 표시된다.
2. `가동 중` 필터를 선택하면 가동 중 설비만 표시된다.
3. 검색어와 상태 필터를 동시에 적용할 수 있다.
4. 설비 행을 클릭하면 상세 정보와 상태 이력이 표시된다.
5. 설비를 `점검·수리 중`으로 변경할 때 사유 없이 저장할 수 없다.
6. 상태 변경이 성공하면 목록의 상태 뱃지와 요약 카드가 함께 변경된다.
7. 전체 설비가 0대인 경우 0으로 나누지 않고 가동 비율을 `-` 또는 `0%`로 표시한다.
8. 목록 조회 실패 시 재시도 또는 새로고침 방법을 안내한다.

## 범위 제외

- 센서·PLC·IoT 실시간 연동
- 시간 기준 가동률 및 OEE 계산
- 설비 예약과 작업 스케줄링
- 예방점검 계획의 반복 일정
- 설비 등록·삭제 마스터 관리
- 복잡한 권한별 메뉴 제어

## 이후 확장 방향

- 상태 변경 이력을 이용한 일별·주별 시간 가동률 계산
- 설비별 작업지시와 현재 투입 LOT 연결
- 고장·점검 사유별 통계
- 설비 알람 및 알림
- 센서 이벤트 수집 API 연결
- 설비 상태를 실시간으로 갱신하는 polling 또는 WebSocket 적용
